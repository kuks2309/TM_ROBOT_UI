## 2. 초기 상태와 서보 OFF 원인

시험 전 실측: DI 워드4 `0x1800`(SVRE=0·SETON=0), DO 6워드 전부 `0x0000`.

**서보 OFF 는 고장이 아니다.** legacy 는 `io_manager` 기동 시 `OUT_GRIPPER_SVON` 을 1로 초기화한다
(`io_manager_node.cpp:171-175`, 조사 정본 §3.6). 그 노드가 떠 있지 않아 `SVON`(비트 90)을 세우는 주체가
없었고, DO 가 전부 0 이므로 서보가 걸리지 않은 것이다. ALARM·ESTOP 이 둘 다 1(negative-true 정상)로
읽히므로 컨트롤러 자체는 전원이 살아 있었다.

## 5. 발견 — 설계에 반영해야 할 것

### 5-1. 무부하 grip 은 **두 가지 종료 양상**을 가지며, `INP` 단독 판정은 오탐을 만든다 (40 표본)

grip 40회 중 6회에서 동작이 정상 종료(BUSY 하강·알람 없음)했는데도 `INP`=0 이었다. 매뉴얼 §8.3 은 푸싱
동작에서 푸싱력이 `Trigger LV` 미만이면 `INP` 가 OFF 로 유지·복귀한다고 규정한다(txt:2108, 2146). 매거진이
없어 반력이 없는 조건이므로 **잡을 대상이 없을 때 `INP` 가 서지 않는 것은 정상 동작**이다.

**grip 30회의 `BUSY` 유지 시간 분포 (60동작 전체):**

| 양상 | 횟수 | 관측된 `BUSY` 유지 시간 |
|---|---|---|
| `INP`=1 (위치 결정으로 종료) | 19 | 0.977 ~ 1.22s · 그리고 **1.721s 1회** |
| `INP`=0 (푸싱 구간 진입, 무부하) | 11 | **1.252 ~ 1.263s 가 10회**(폭 11ms) · 그리고 2.136s 1회 |

- **살아남은 사실**: `INP`=0 인 11회 중 **10회가 11ms 폭**(`1.252~1.263s`)에 집중한다. 거리에 비례하는
  이동이 아니라 **고정 길이의 푸싱 시도 구간**이 붙은 형태로 읽힌다(매뉴얼 §8.3 정합).
- **철회한 주장**: 40 표본 시점에 "두 집합이 완전히 분리된다 · 80ms 공백 · 겹침 0" 이라고 적었으나
  **3차에서 반증됐다** — 2회차 grip 이 `1.721s` 인데 `INP`=1 이다. 즉 **동작이 길다고 `INP`=0 이 되는 것은
  아니다.** 경위·재발 방지는 mistake `2026-08-13-006`.

⚠ **확정하지 않은 것**: 같은 무부하 조건에서 어떤 회차가 그 11ms 구간(푸싱 시도)에 들어가는지는 미확정이다.
`BUSY` 유지 시간으로는 예측되지 않는다(1.22s→INP=1, 1.252s→INP=0, 1.721s→INP=1).

**M2 FSM 반영 사항**: grip 완료 판정은 `INP` 단독이 아니라 `BUSY` 하강 + 매거진 감지(MGZ) 조합이어야 한다.
`gripper_stack.yaml` 의 `timeouts.inp_ms: 1000` 을 grip 실패 판정에 쓰면 무부하 시 **40회 중 6회 오탐**이 난다.

### 5-4. 3차 실행의 시작 조건 차이 (도구 결함 1건)

3차 로그 첫 줄이 `BUSY=-1 INP=-1 …`(전 신호 -1)로 남았다. `-1` 은 "아직 `io_resp` 를 한 번도 못 받음"을
뜻하며, 도구가 `pump(0.5)` 후 바로 상태를 찍기 때문이다. 그 결과 `SVRE != 1` 로 오판해 이미 서 있던 `SVON` 을
한 번 더 인가했다(무해). 3차 1회차 release 가 `1.272s`(다른 59회는 0.5s 대)로 이례적인 것도 이 구간과
겹친다 — ⚠ 인과는 확정하지 않는다.

**조치 필요**: 시작 상태 관측 전에 **첫 이미지 수신을 기다리는 대기**를 넣어야 한다.

### 5-3. `OUT0~5`(실행 스텝 반향) 관측 타이밍

단발 시험에서는 복귀 후 `OUT1=1`(step 2)이 관측됐으나, 10사이클 도구에서는 사이클 중 항상 `OUT=0` 이었고
시작·종료 상태에서만 `OUT=2` 였다. ⚠ `DRIVE` 하강 후 반향이 유지되는 구간과 우리 관측 시점(복귀 0.3초 후)이
어긋난 것으로 보이나 확정하지 않았다 — 반향을 완료 판정에 쓰려면 별도 계측이 필요하다.

## 5-5. 매거진 감지 2점 — 실측 확정 (2026-08-13)

금속·매거진 근접 시험에서 **전이 48건**을 관측했다(105초·5,107 프레임, DI 80비트 전수 감시).

| 시각 | 관측 |
|---|---|
| 54~78s | DI[24]·DI[25] 산발 `1↔0` — 금속 근접 시험 구간 |
| **92.43s** | DI[24] `1→0` — MGZ#1 감지 |
| **92.47s** | DI[25] `1→0` — MGZ#2 감지 (#1 대비 **40ms** 차) |
| **96.39s** | DI[24]·DI[25] **같은 프레임**에 `0→1` — 동시 해제 |

**확정 사항**

- **경로 정상** — 센서·배선·DI 모듈이 전이를 만든다. 이전 관측(`raw=1` 불변)은 경로 이상이 아니라
  **트리거 미발생**이었다.
- **극성 확정(실측)** — 원시 `0` = 감지. legacy 판정 `getInput(...) == 0`
  (`amr04.../gripper_node.cpp:299·1062·1076·1096`)·우리 config `magazine.detected_level: 0` 과 일치한다.
  조사 정본 §결함표 8번의 "⚠ 전기 실측 미실시" 가 이로써 해소된다.
- **`require_both` 성립** — 매거진 안착 시 2점이 40ms 차로 함께 감지되고, 제거 시 같은 프레임에 함께
  해제된다. grip 인터록 조건(2점 모두 감지, `gripper_stack.yaml interlock.*.grip: require_both`)이
  실기에서 실제로 만들어진다.
- **손 가림은 부적합한 시험 방법** — 센서가 근접센서(도면 BOM p.4 항목 38: OMRON E2E-X9C212)라
  비금속에는 반응하지 않는다. 조사 정본 §결함표 8번의 "손 가림 시험으로 0/1 확인" 서술은 **정정 대상**이다.
  ⚠ 모델 데이터시트는 `references/` 에 없어 검출거리·대상 재질은 미확정이다.

## 5-6. legacy 원점복귀 절차는 생략할 수 없다 — 2026-08-15~16 실측

2026-08-15 시험에서 step2(open)가 **2.485~2.503초 후 알람(그룹 D·서보 차단)으로 4회 연속 실패**했다.
매거진 유무·접촉 여부와 무관했고(무부하 조건에서도 실패), 물리 간섭도 없었다(사용자 확인).

**원인은 시험 절차였다.** 실패한 4회는 전부 `알람 리셋 → SVON → 곧바로 스텝 구동` 순서였고,
`SETUP`(원점복귀)을 넣자 즉시 정상화됐다.

| 시험 (2026-08-16) | 결과 |
|---|---|
| SETUP 원점복귀 | BUSY 4.459s 완료 · SETON 확립 |
| step1 | 0.880s · INP 확립 |
| **step2** | **0.420s · INP 확립** ← 직전 4회 연속 실패하던 것 |
| step3 | 0.840s · INP 확립 |
| step4 | BUSY 미상승 · 즉시 알람 — **미등록 스텝**(프로파일 3종만 등록됐다는 방증) |

이어서 legacy `returnToOrigin()`([amr04.../gripper_node.cpp:362-465](../../../../../../amr04_20260324/src/tc_gripper/src/gripper_node.cpp))
절차를 그대로 옮겨 실행하자 **개폐 6/6 무알람** 통과했다.
