# gripper_motion 인벤토리 (M2 신규 — coding SOP §2 계획 단계 표)

> **대상**: `Actuators/gripper/gripper_motion/` — 그리퍼 시퀀스 FSM(Finite State Machine).
> **ROS-free** — 포트 3종(M1 계약)만 소비한다. rclcpp·Modbus 심볼 0(`⟦CI:gripper-io-single-master⟧`).
> **왜 필요한가**: M1 은 «비트를 원자적으로 쓴다» 까지만 책임진다. **순서 규칙**(알람 후 원점복귀,
> 완료 판정, 인터록)을 아는 계층이 없어 2026-08-15~16 실기에서 절차 누락으로 4회 연속 실패했다
> (mistake `2026-08-16-004`). 이 표의 전이 규칙은 그 실측에서 나왔다.

### 되살아 있던 실기 실패 경로

`homing_required_` 를 세우는 곳이 알람을 관측한 **일부 상태**(BUSY 대기 4종)뿐이라, `kServoOn`·
`guardBeforeDrive`·`verifyComplete` 에서 알람으로 실패하면 이력이 남지 않았다. 알람이 외부에서
해제되면 `SETON` 래치가 살아 있어 `needsHoming()` 이 false → **원점복귀 없이 스텝 구동**.
8/15 실기 실패(15회 중 8회 알람)의 재현 경로가 그대로였다. 게다가 트리거가 알람뿐이라
R1 이 문서로 못박은 «서보 차단·전원 재투입» 두 트리거는 **코드에 존재하지 않았다**(lane A 실행 확인).

`kServoOn` 분기에 `kOrigin` 전용 경로가 없어, 정상 완주 뒤 «원점으로 보내» 를 누르면 `SETUP` 은
한 번도 서지 않고 프로파일 스텝이 구동됐다(lane A 실행: `SETUP` 상승 0회 · `write_step` 21회 · step3).
원점을 의심할 때 쓰는 명령이 원점복귀를 하지 않는 상태였다.

### 죽은 설정 2개

`feedback_stale_limit`·`setup_hold` 는 `MotionConfig` 에 있고 `validate()` 가 검사까지 했지만
`gripper_fsm.cpp` 에서 **참조 0건**이었다. 값을 1ms 로 두든 9999ms 로 두든 거동이 동일함을
실행으로 확인했다(lane A probe [M]). 1라운드에서 «M6·M7 반영» 이라고 보고한 것의 실체다.

### 시험 자체의 결함 4건 (적발·수리)

- **SIL S3 의 «송신 0회» 단언이 항등식**이었다 — 기준값을 요청 *뒤에* 담아 자기 자신과 비교했다.
  수리 후 «인터록 판정 전에 스텝 인가» 뮤턴트를 넣자 red 2건이 떴다(수리 전에는 통과).
- **«정상 상태면 원점복귀를 건너뛴다» 시험이 본문에서 원점복귀를 수행**하고 있었다(`passHoming()` 호출).
  실제 건너뛰기 경로(원점복귀 완주 → 매거진 투입 → grip)로 다시 쓰고 `SETUP` 재인가 0회를 단언한다.
- **`CHECK(clears > 0)` 이 항진 단언**이었다 — 페이크가 실패를 반환하기 *전에* 카운터를 올린다.
  복귀 성립은 호출 횟수가 아니라 **최종 레벨**로 단언한다.
- **SIL 플랜트가 매거진 2점을 같은 값으로 냈다** — `require_both` 와 `any_detected` 가 SIL 에서
  절대 갈리지 않았다. 센서를 독립시키고 «1점만 감지» 시나리오(S8)를 추가했다.

### 설계 판단 2건

- **`total_deadline` 은 감시견이지 단계 타임아웃이 아니다.** 단계 상한의 직렬 최악합(44.5s)보다
  짧게 잡으면 각 단계를 모두 지킨 정상 시퀀스가 잘린다. 운영값을 **45000ms** 로 올리고
  `gripper_stack.yaml` 에 `total_deadline_ms` 키를 신설했다(그 전에는 키가 없어 M4 조립 시
  0 이 들어가 기동이 거부됐을 것이다). 발동은 «단계 타임아웃이 듣지 않았다» 는 신호로 읽는다.
- **매거진을 문 상태의 냉시동 grip 은 성립하지 않는다.** 원점복귀는 `forbid_any`, grip 은
  `require_both` 라 배타적이다 — 운용 순서는 «빈 상태로 원점 → 매거진 투입 → grip» 뿐이다.
