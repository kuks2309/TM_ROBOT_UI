## 왜

ADR-008 M0(계약 동결) 착수. 사용자 승인 결정 5건을 계약으로 옮겼다 — 스킬 폴더명 `Robot_Gripping`,
조정 범위는 프로파일 선택만, Q3 는 보류하되 액션+lifecycle 형태 고정, **현행 3스텝 파리티 + 프로파일 확장 봉인**.

설계에서 갈린 지점 2개:

1. **스텝 비트를 개별로 여는 API 를 두지 않았다** — `write_step` 6비트 원자 쓰기가 유일 경로다.
   개별 비트 API 가 있으면 "IN0 만 세워진 채 DRIVE" 같은 중간 상태가 물리적으로 가능해진다.
2. **극성 해석을 계약이 흡수했다** — `ALARM`·`ESTOP` 는 negative-true 라(LECP6 OM page 28)
   원시 0/1 을 소비자가 해석하게 두면 정상과 이상이 뒤집힌다. `has_alarm`·`is_emergency_stop` 로만 판정한다.

기존 리뷰 지적 3건(`docs/code_review/signal_buzzer/2026-08-04.md` 함수 #1·#2·#5·#6)을 같은 패턴에서 재발시키지 않도록
`Result<T>` 를 조정했다 — `value()` 는 `optional::value()`(NDEBUG UB 제거), 기본 생성자 private, `error()` 는 가드 삼항.

## 외부 리뷰 반영 (Gemini lane, `VERDICT: CHANGES_REQUESTED`)

Codex lane 은 크레딧 소진으로 실패했고 Gemini(`gemini-2.5-flash`) 결과만 유효하다. 지적 9건을 1차 소스·코드로 대조해 4건 반영, 3건 기각, 2건은 미결로 승격했다.

| 지적 | 판정 | 처리 |
|---|---|---|
| `is_ready_for_drive` 에 SETON 누락 (High) | **타당** — 매뉴얼 page 38 §8.1 "return to origin … before starting the positioning or pushing operation" | `kSetOn` 조건 추가 + `is_ready_for_origin` 분리(원점복귀는 SETON 불요). 테스트 4케이스 추가 |
| `has_alarm`/`is_emergency_stop` 가 stale 에서 오판정 (Medium) | **부분 타당** — 방향은 보수적(알람 있음)이라 안전하나 표시 경로가 통신 단절을 알람으로 둔갑시킬 수 있다 | 헤더에 stale 취급 규약 명시 — 표시·진단 경로는 fresh 로 "판정 불가"와 구분 |
| `get` 시프트 폭 위험 (Low) | **근거 정정 후 타당** — 현재 코드에 UB 는 없다(정수 승격으로 int 시프트). 실제 위험은 신호 확장 시 `bits`(16) 초과분이 조용히 사라지는 것 | `static_assert(kCount <= 16)` 추가 |
| 코봇 브리지 ↔ 액션 이중 명령 중재 부재 (Medium) | **타당** | ADR-008 미결 Q5 로 등록 |
| Rx 시리얼 백엔드가 병렬 I/O 형 계약에 안 맞음 (Medium) | **타당** | ADR-008 Q4 에 위험으로 병기 |
| `manual_mode` 인터록 전부 `none` (High) | **부분 기각** — legacy 파리티 그대로이며 config 로 변경 가능(코드 강제 아님). "auto_mode release/home 도 강제" 는 사실과 다름 | 정책 결정 항목으로 사용자에게 상신 |
| Modbus 다중 마스터 경합 (High) | **기각** — 본 계약은 `IRemoteIoStationPort` 를 소비만 하며 자체 소켓을 열지 않는다. `⟦CI:gripper-io-single-master⟧` 가 이를 강제한다 | 조치 없음 |
| `clear_step_and_drive` 만 있어 "DRIVE 만 내리기" 불가 (Medium) | **기각** — `write_line(kDrive, false)` 가 그 경로다 | 조치 없음 |
| `Duration`=milliseconds 강제 (Low) | **기각** — ROS 변환은 조립층 소관이고 계약을 ROS 타입에 묶으면 ros-free 규율 위반 | 조치 없음 |

## 외부 리뷰 2라운드 (Codex lane, `VERDICT: CHANGES_REQUESTED`)

ChatGPT 인증으로 전환 후 재실행. High 10 · Medium 11 · Low 2 = 23건. 계약에 반영한 것:

| 지적 | 반영 |
|---|---|
| `fresh`/`stamp` 의 생성 기준·상관 수단 부재 (High) | `seq`(단조 증가 입력 이미지 번호)를 두 스냅샷에 추가 + stamp 는 **수신 시각 고정**(캐시 반환 시 재기록 금지) 계약 명문화 |
| 극성 판정이 stale 을 무시한 `bool` (High, Gemini 와 중복) | `SignalState{kUnknown,kInactive,kActive}` 3상태로 교체 — 통신 단절이 "정상"으로도 "알람"으로도 새지 않는다 |
| 피드백·매거진 조합 판정의 TOCTOU (High) | `same_image(feedback, magazine)` 추가 — seq 불일치면 조합 인터록 판정 금지 |
| `write_step`/`clear_step_and_drive` 원자성·부분 적용 표현 부재 (High ×2) | 단일 RMW 커밋·read-back 확인 의무를 계약 주석에 명문화 + `HalError::kIndeterminate` 신설(재시도 전 상태 재확인 요구) |
| 액션 필드 배타성 미정의 (High) | 명령별 유효 조합 표를 IDL 머리에 명시 + `RESULT_INVALID_REQUEST` |
| 정비용 직접 스텝의 권한 부재 (High) | `COMMAND_STEP` 분리 + config `maintenance{allow_direct_step:false, allowed_steps:[1,2,3], require_manual_key:true}` |
| `RESULT_NOT_READY` 가 4가지 원인을 뭉갬 (Medium) | `STALE`/`SERVO_NOT_READY`/`NOT_HOMED`/`ESTOP_ACTIVE`/`ALARM_ACTIVE` 분리 |
| 취소·선점 결과 부재 (Medium) | `CANCELED`·`ABORT_FAILED`·`STATE_INDETERMINATE` 추가 |
| 알람 그룹이 문자열에만 (Medium) | `alarm_group` enum + `alarm_raw_bits` 구조화 필드 |
| 원점복귀 전용 타임아웃·펄스 폭 부재 (Medium ×2) | `timeouts.origin_busy_rise/fall_ms` + `pulses.*` 신설, phase 에 `ORIGINATING`/`WAIT_SETON`/`RESETTING` 추가 |
| `Result::err(kNone)` 허용 (Medium) | `kNone` 입력을 `kProtocol` 로 승격 — 모순 상태 생성 불가 |
| enum 센티널 처리 불일치 (Medium) | `write_line` 이 `kCount` 를 `kOutOfRange` 로 거부하도록 계약 명시 |
| `Health` 시점 식별 불가 (Medium) | `last_seq`·`last_error` 추가 |
| 주소 공간 기준 불명확 (Medium) | config 주석에 "스테이션 입력/출력 이미지의 절대 비트 인덱스, Modbus 레지스터 주소 아님" 명시 |
| 타임아웃 값 검증 규칙 부재 (Low) | `validation{all_timeouts_positive, stale_must_be_shortest, …}` 신설 |
| `value()` rvalue dangling (Low) | ref-qualified overload — rvalue 는 값 이동 반환(`static_assert` 로 회귀 고정) |
| step 0 금지를 HAL 이 강제 (Medium) | 주석으로 위임 관계 명시(범위는 HAL, 허용 목록은 config) — 범위 상수는 유지 |

**미결로 승격**: 배포 토폴로지(Q7) — 명령 포트가 스테이션 포트를 **같은 프로세스에서 주입받는지, ROS 서비스로 요청하는지**가 정해지지 않았다. legacy 는 `io_service` 서비스 경유였다. 별도 노드로 두면 계약이 IPC 요청/응답(요청 ID·적용 확인·거절 사유)으로 바뀌어야 한다.

**기각**: "다중 마스터 경합"(스테이션 단일 writer 를 소비만 함 — Gemini 와 동일 오독), 백엔드 연결 스키마 부재(연결 설정은 `Remote_IO_Station` 소유).
