1. **사용자가 명시적으로 지시한 사항만 수행한다.**
2. 추가적인 "개선"이나 "최적화"를 임의로 하지 않는다.
3. 요청하지 않은 파일을 수정하지 않는다.
4. 요청하지 않은 기능을 추가하지 않는다.
5. 질문이 있으면 먼저 물어본다.

# Claude 작업 지침

## 핵심 원칙 (8대 원칙)
1. **모든 의도와 결정을 즉시 기록한다**
2. **객관적 사실로 판단한다** (코드·로그·매뉴얼 인용, 추측·기억·일반 지식 금지)
3. **모르는 것은 "확인되지 않음" 으로 명시한다**
4. **사용자가 지시한 사항만 수행한다**
5. **관련 이론을 철저히 조사한 후 시작한다** (공식 문서·매뉴얼·기존 코드 우선)
6. **코딩 전 구조를 제시하고 사용자 승인을 받는다**
7. **임의로 기능을 추가하거나 변경하지 않는다**
8. **검증·보고는 파일·줄·실제 출력을 인용한다** ("동일합니다" 금지)

## 금지 사항
- 사용자가 요청하지 않은 모델 구조 변경 금지
- 요청하지 않는 코딩 금지
- 코딩 전에 프로그램 구조 먼저 제시하고 코딩은 승인 받을 것
- 코딩 전에 중복 함수, 중복 변수 확인할 것

## 코드 수정 규칙
- 기존에 지시한 코드 로직을 임의로 변경하지 않는다
- 이전에 승인받은 코드 구조를 유지한다
- 변경이 필요하면 반드시 사유를 설명하고 승인받는다

## 코딩 전 필수 확인 사항
- **중복 함수 확인**: 새 함수 추가 전 기존에 동일/유사 기능의 함수가 있는지 검색
- **중복 변수 확인**: 새 변수 추가 전 기존에 동일/유사 목적의 변수가 있는지 검색
- **기존 코드 재사용**: 중복이 발견되면 새로 만들지 말고 기존 코드를 활용

## 작업 경계 점검 (증거 기반)

작업 시작 시:
- 이번 지시의 범위를 1~2줄로 요약하고, 이번 작업에 적용되는 본 문서의 금지 규칙을 명시한 뒤 시작한다.
- 코드 수정이 필요하면 대상 파일·함수 목록과 변경 방식을 먼저 제시하고 승인받는다.
- 범위 밖 작업이 필요해 보이면 수행하지 말고 먼저 문의한다.
- 지시가 본 문서의 금지 규칙과 충돌하면 즉시 수행하지 말고, 금지 항목 해제(본 문서 수정) 승인을 먼저 받은 뒤 구조 제시·승인 절차로 진행한다.

작업 단위 종료 보고에 반드시 포함:
1. 변경 파일 목록과 각 변경이 어느 지시에 대응하는지 1:1 매핑
2. 미지시 변경(임의 추가·수정) — 있으면 사유와 함께 명시, 없으면 "없음" 명기
3. 기존 함수 수정 시 변경 전/후 핵심 라인 인용 ("동일합니다" 서술 금지)
4. 검증 근거: 파일 경로·줄 번호·실제 실행 출력 인용
