## 3. 연결 구축 상세 (재현 가능 절차)

### 3-1. 로봇 발견

- 저장 설정의 구주소(`169.254.183.219`)는 응답 없음 → eno1 원시 소켓 감청으로 브로드캐스트 포착
- **실제 로봇: `169.254.122.16`** (MAC(Media Access Control) `00:10:f3:bf:3f:60` = Nexcom 산업용 PC). APIPA(Automatic Private IP Addressing) 주소라 향후 변동 가능 — 안 잡히면 같은 방식으로 재탐색
- 포트 5891에서 `$TMSVR` 스트림 수신으로 로봇 확정

### 3-2. 네트워크 (영구 설정 완료)

```bash
# eno1 프로파일에 link-local 대역 추가됨 (재부팅 유지)
nmcli -g ipv4.addresses con show eno1   # → 192.168.1.5/24, 169.254.183.100/16
ping 169.254.122.16                      # 0.26ms
```

⚠ 잔여: eno1 의 `192.168.1.5/24`가 무선 서브넷과 중복 — 라우팅 혼선 소지(미조치)

### 3-3. TMflow(로봇 쪽) 설정 — 완료 상태

1. Ethernet Slave **Enable** (`설정 → 연결 → Ethernet Slave`), Data Table **49항목** (표준 44 + `End_DO3`·`Ext_Safeguard`·`Operation_Mode` 추가)
2. Listen 노드 포함 프로젝트 **`ROS2_COM4`** 실행 (로봇 스틱 Play) → 포트 5890 열림
   - 플로우 구조: Start → init_robot_command → check_robot_command 분기 → 0번 분기의 `Listen1` 대기 (사진: `TM_Export/images/20260123/tm_flow_script/`)

### 3-4. 이 PC 쪽 기동 (부팅 후 재현 커맨드)

```bash
cd ~/Project/T-Robotics/kkw/TM_Robot_ros2_ws
source /opt/ros/humble/setup.bash && source install/setup.bash
ros2 run tm_driver tm_driver robot_ip:=169.254.122.16
# 확인: ros2 topic echo /feedback_states --once   → is_svr/sct_connected: true
# GUI: ros2 launch tm_task_manager task_manager.launch.py robot_ip:=169.254.122.16
```

주의: launch/config 의 robot_ip 기본값은 구주소(`169.254.183.219`)이므로 **반드시 인자로 덮어쓸 것**

### 3-5. 모션 검증 (실기)

- `set_positions` 서비스 단위 실측 확정: 관절 **rad**·직교 **m/rad**, velocity **rad/s**(π=100%), acc_time **초** ([tm_command.cpp:42-53](../../src/Robot/tmrobot_official_packages/tm_driver/src/tm_command.cpp) `degs()` 변환) — 내부 문서(`TM_Robot_Motion_Control_Reference.md`)의 "acc_time: ms" 표기는 오기
- J6 +1°(속도 5%) → 정확 도달, 타 관절 불변 → 원위치 복귀 PASS

### 3-6. 제어 GUI(Graphical User Interface) 기동 (오후)

- **기동 커맨드 (또는 바탕화면 "TM Task Manager" 숏컷)**:
  ```bash
  PYTHONNOUSERSITE=1 DISPLAY=:0 ros2 launch tm_task_manager task_manager.launch.py robot_ip:=169.254.122.16
  ```
- `PYTHONNOUSERSITE=1` 필수 — pip user 의 NumPy 2.2.6 이 cv_bridge 를 깨뜨림(apt 정합 스택으로 우회). `python3-waitress` apt 설치, 심볼릭 링크 `/home/amap/TM_Robot_ros2_ws → 실제 워크스페이스`(구경로 하드코딩 일괄 해소) 적용됨

### 3-7. 카메라 비전 파이프라인 (오후)

```
[로봇 카메라] → 비전 잡 TM_IMG_Send(찾기→외부 감지, URL=169.254.183.100:6189/api/DET)
             → HTTP POST → [tm_camera_bridge :6189] → /techman_image → GUI 표시
```

- 로봇 프로젝트("listen node DIO(Digital Input Output) test")에 비전 잡 `TM_IMG_Send` 생성(티치펜던트). 플로우 노드 연결 불필요 — `Vision_DoJob_PTP("TM_IMG_Send", 100, 500)` 스크립트로 실행(무이동 버전 `Vision_DoJob()`은 초기 위치 잡에서 실패 — TMscript v2.18 §13.26)
- GUI 사용법: **Image Capture** 버튼 = 1장 촬영·표시 / **카메라 시작·정지** = 라이브 뷰(실효 약 1장/초, 상한은 촬영 파이프라인 소요) — 라이브 뷰 중 로봇이 촬영 위치를 점유하므로 이동 작업 전 정지 권장
