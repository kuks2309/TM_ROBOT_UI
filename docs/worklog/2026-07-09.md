## 9. 네트워크 — 원격 기기 웹 GUI 접속 수정
- **증상**: 다른 노트북(같은 WiFi `T-robotics5G`, IP 192.168.1.32)에서 `http://192.168.1.10:3000` 무한로딩. Jetson 자체는 정상(HTTP 200), 방화벽 없음.
- **원인**: Jetson eno1(유선)에 `192.168.1.5/24`가 붙어 WiFi(`wlP1p1s0` 192.168.1.10/24)와 **서브넷 중복** → `ip route get 192.168.1.32`가 eno1로 잘못 나감(응답 유실).
- **해결(영구)**: `nmcli con mod eno1 ipv4.addresses "169.254.183.100/16"`(192.168.1.5 제거, 로봇용 169.254 유지) + `con up`. 검증: 노트북 경로 → wlP1p1s0, 로봇 경로 → eno1 169.254 유지(무영향). 롤백은 addresses 원복.
- **결과(확인 완료, 2026-07-09)**: 원격 노트북(192.168.1.32)에서 **웹 GUI 접속 + jog 실동작 성공**. → 라우팅 수정이 진짜 해결책이었음. (Jetson→노트북 ping 실패는 노트북 윈도우 방화벽 ICMP 차단일 뿐 무해 — AP Isolation 아님.) **다른 기기로 로봇 제어 가능** 확인.
- **주의**: eno1 재적용으로 인터페이스 순간 바운스 → 로봇 재개 시 tm_driver/브리지 재기동 필요할 수 있음(작업 시 로봇 정지 상태였음).
