# 2026-07-13 13:40 (KST) — 헛도는 타입체크 명령으로 "검증 통과" 반복 선언

## 무엇을 했는가

웹 클라이언트(`~/Desktop/TRobotics_Client`) 를 수정할 때마다 `npx tsc --noEmit` 을 실행하고
그 exit code 0 을 근거로 **"tsc exit 0 — 통과", "타입체크 통과 ✓"** 라고 사용자에게 반복 보고했다.
이번 세션에서만 JPEG 압축 구독 변경, 모션 게이트 리셋, Vision 라이브 뷰 구현 등 여러 차례
같은 방식으로 "검증 완료" 를 선언했다.

실제로는 이 프로젝트의 `tsconfig.json` 이 **solution 스타일**이다:

```json
{ "files": [], "references": [{ "path": "./tsconfig.app.json" }, { "path": "./tsconfig.node.json" }] }
```

`files: []` 이므로 `tsc --noEmit` 은 **어떤 파일도 검사하지 않고 항상 exit 0** 을 낸다.
올바른 명령은 `tsc -b`(참조를 따라감) 이며, `package.json` 의 `build` 스크립트가 이미
`"build": "tsc -b && vite build"` 로 그것을 쓰고 있었다.

발각 경위: TaskEditor 의 인라인 조그를 공용 컴포넌트로 추출하면서 `motionEnabled` 선언을
같이 지웠는데(시퀀스 실행 버튼도 그 변수를 쓰고 있었다), `tsc --noEmit` 은 여전히 exit 0 을
냈다. 사용처는 있는데 선언이 없으면 반드시 에러여야 하므로 모순을 추적해 원인을 찾았다.
`tsc -b` 로 재실행하니 `TS2304: Cannot find name 'motionEnabled'` 2 건이 즉시 잡혔다.

## 무엇이 잘못이었나

  실제 회귀 검증이 성립하지 않는 명령을 회귀 검증으로 보고했다.
- `docs/claude_guideline/issue_fix/issue_fix.md` §Step 5 검증 — "증거 없는 '고쳤다' 선언 금지 —
  검증 출력으로 입증한다." 출력이 공백(에러 0)인 것을 증거로 오인했다.
- 루트 `CLAUDE.md` 핵심 원칙 4 — "증거 없이 '동일합니다' 말하지 않는다."

## 원인 분석

**가시성**: 규칙은 명확히 보였다. coding.md §0 은 바로 이 실패 모드("green ≠ good")를
문자 그대로 경고하고 있었고, 나는 이 세션에서 coding.md 를 읽기까지 했다.

**강제력 부재가 진짜 구멍**: 도구의 exit code 만 확인했을 뿐, **그 도구가 대상 파일을 실제로
검사했는지**는 아무도 확인하지 않았다. "0 errors" 와 "0 files checked" 를 구분하는 장치가 없었다.
`tsc --noEmit` 은 일반적인 React+TypeScript 프로젝트에서 통하는 관용구라 의심 없이 사용했고
(wrong-assumption 성격), 프로젝트가 이미 `package.json` 에 정답(`tsc -b`)을 갖고 있었음에도
`package.json` 의 build 스크립트를 확인하지 않았다.

핵심 교훈: **검사가 0 을 냈을 때 "무엇이 0 인가"(에러 0 인가, 검사한 파일이 0 인가)를 묻지 않았다.**

## 재발 방지

**강제 메커니즘 — SessionStart 주입**: 프로젝트 메모리
`memory/trobotics-client-webgui.md` 에 웹 클라이언트의 **검증 명령 정규형**을 못박았다.
이 메모리는 매 세션 시작 시 자동 주입되므로, 다음 세션은 `tsc --noEmit` 을 쓰지 않는다.

기록한 내용:
- 웹 클라이언트 타입체크는 **반드시 `npx tsc -b`** (또는 `npm run build`). `tsc --noEmit` 은
  `tsconfig.json` 이 solution 스타일(`files: []`)이라 **아무것도 검사하지 않고 exit 0** 을 낸다.
- 검증 보고 시 "에러 0" 과 "검사 파일 0" 을 구분한다 — 도구가 대상을 실제로 검사했는지 먼저 확인.

**적용 확인**: 본 사건 직후 `npx tsc -b` 로 재검증하여 실제 에러 2 건(`TS2304`)을 검출·수정했고,
`npm run build`(= `tsc -b && vite build`) 까지 통과시켜 회귀를 닫았다.
