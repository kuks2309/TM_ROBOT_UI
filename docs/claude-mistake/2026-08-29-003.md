# 2026-08-29 16:38 (KST) — Move_Line("TPP") 좌표계 의미를 매뉴얼 검증 없이 단정 → 실기 오이동(사고)

## 무엇을 했는가

팔래트 진입 레시피에 `move_linear`(내부적으로 TM 스크립트 `Move_Line("TPP", dx,dy,dz,...)`) 를 넣고, 사용자에게 "공구 좌표계 상대 이동이므로 offset Z+ 를 넣으면 마커 쪽으로 직진 진입", "offset X·Y 는 팔래트 표면과 평행"이라고 안내했다. 근거는 저장소 코드의 docstring(`tm_robot_script_motion.py` "Move_Line(\"TPP\") 공구 좌표계 상대 직선 이동")뿐이었고, TM(Techman) 스크립트 매뉴얼 원문 대조는 하지 않았다.

## 무엇이 잘못이었나

- 루트 `CLAUDE.md` 외부 참조 규칙: "외부 참조 문서(매뉴얼·datasheet·SDK·표준) 트리거 감지 시 의무 선행 점검 … **기억 의존 추정(환각) 금지**" — TM 스크립트 함수의 좌표계 의미는 벤더 매뉴얼 소관인데 매뉴얼 확인 없이 단정했다.
- 같은 대화에서 "TPP 의 원어 전개는 매뉴얼 대조 없이 적지 않는다"고 스스로 선언하고도, 정작 **의미(좌표계)는 검증 없이 단정**했다 — 전개보다 의미가 훨씬 위험한 주장인데 기준을 거꾸로 적용했다.
- 결과: 실기에서 X,Y 이동이 사용자가 기대한 마커 평행 방향과 다르게 나가 충돌 사고 발생(2026-08-29 16:38 사용자 보고: "move_linear 가 tcp기준으로 안 움직여서 사고 났음"). 로봇 에러 없음 확인.

## 사용자 지적

> "지금 move_linear 가 tcp기준으로 안 움지겨서 사고 낫음  x,y 이동이 마커와 평행하게 움직여야 하느데"

## 원인 분석

가시성·강제력 점검: 외부 참조 규칙은 루트 CLAUDE.md 에 등록되어 세션 컨텍스트에 있었다(모름 아님). 코드 docstring 이 "공구 좌표계"라고 적혀 있어 그것을 1차 근거로 삼았는데, 그 docstring 자체가 검증된 적 없는 주장이었다(레거시 코드의 이해 부채). 로봇 실모션 지시라는 고위험 맥락에서는 코드 주석이 아니라 벤더 매뉴얼이 권위인데, 참조 저장소·references/ 에 TM 스크립트 매뉴얼이 없다는 사실을 확인하고도 "확인 불가"를 밝히는 대신 docstring 을 사실로 승격시켰다. 위험도(로봇 충돌)와 근거 등급(미검증 주석)의 불일치를 걸러줄 게이트는 없다.

## 재발 방지

- 즉시(운영): `Move_Line`/`move_linear` 는 TM 스크립트 매뉴얼 원문으로 TPP/CPP 좌표계 의미가 검증될 때까지 팔래트 작업 레시피에서 사용 중지. 마커 평행 이동은 스크립트 의미에 의존하지 않는 검증된 경로(마커 frame 변환 + SetPositions LINE_T 절대 목표 — sdc_palette_inlet_move 방식, 실기 검증 완료)로 대체한다.
- 지식 자산: `tm_robot_script_motion.py` docstring 의 "공구 좌표계" 주장을 이해 부채로 등록(debt registry — 매뉴얼 확보 시 원문 대조로 검증·정정). TM 스크립트 매뉴얼(Expression Editor manual) 확보를 references/ 과제로 남김.
- 원칙: 로봇 실모션에 관한 좌표계·방향 주장은 (a) 벤더 매뉴얼 원문 또는 (b) 실기 저속 검증 중 하나 없이는 "확인되지 않음"으로만 답한다.
