# drawio 시각 검토 체크리스트 (Layer B)

`drawio_capture.sh` 가 만든 PNG 를 **Read 도구로 열어** 아래를 순서대로 확인한다.
린트(Layer A)가 이미 통과한 상태를 전제하므로, 여기서는 **좌표로 계산되지 않는
것**만 본다. 한 항목이라도 ✗ 면 `.drawio` 를 고치고 린트부터 다시 돌린다.

## 왜 눈으로 봐야 하는가

린트는 숫자로 증명되는 것만 잡는다. 폰트 실측 오차, 라벨과 화살표의 시각적
간섭, 전체 밀도와 시선 흐름은 렌더 결과에만 나타난다. 반대로 여기서 "박스가
겹쳤다" 같은 걸 눈으로 찾고 있다면 린트가 놓친 것이므로 규칙을 고쳐야 한다.

## 체크리스트

### 1. 글자 (린트 L5 의 실측 확인)

- [ ] 박스 안 글자가 테두리를 넘지 않는가 — 특히 한글·영문 혼용 라벨
- [ ] 글자가 잘리거나 `...` 로 생략되지 않았는가
- [ ] 줄바꿈이 단어 중간을 어색하게 끊지 않는가
- [ ] 폰트 크기가 박스별로 들쭉날쭉하지 않은가
- [ ] 두부(tofu, □) 나 깨진 글자가 없는가 — 폰트 미설치 신호

### 2. 화살표 (린트 L4·L7·L9 의 실측 확인)

- [ ] 사선이 하나도 없는가 — 전부 수평·수직과 직각 꺾임인가
- [ ] 불필요한 계단 꺾임(작게 지그재그)이 없는가
- [ ] 화살표가 박스를 관통하지 않는가
- [ ] 화살표끼리 겹쳐 하나처럼 보이는 구간이 없는가
- [ ] 화살촉이 박스 테두리에 정확히 닿는가 (뜨거나 파고들지 않음)
- [ ] 교차가 불가피한 곳이 몇 군데인가 — 3곳 이상이면 배치를 다시 본다

### 3. 라벨

- [ ] 엣지 라벨이 선·박스·다른 라벨과 겹치지 않는가
- [ ] 라벨이 어느 화살표 것인지 한눈에 구분되는가
- [ ] 라벨 배경이 선을 가려 흐름이 끊겨 보이지 않는가

### 4. 배치와 흐름

- [ ] 흐름 방향이 일관되는가 — 위→아래 **또는** 좌→우 중 하나로 통일
- [ ] 시작점과 끝점이 시각적으로 분명한가
- [ ] 같은 층위의 박스들이 한 줄로 정렬되어 있는가
- [ ] 빈 공간이 한쪽에만 쏠려 있지 않은가
- [ ] 다이어그램이 페이지(회색 경계) 안에 들어오는가

### 5. 색과 대비

- [ ] 배경과 글자 대비가 충분한가 (연한 배경에 연한 글자 금지)
- [ ] 색이 의미를 가진다면 같은 의미에 같은 색을 썼는가
- [ ] 색맹 상태에서도 구분되는가 — 색만으로 구분하지 말고 모양·테두리 병용

### 6. 전체 인상

- [ ] 처음 보는 사람이 5초 안에 "무엇에 대한 그림인지" 알 수 있는가
- [ ] 요소가 너무 빽빽하거나 너무 성기지 않은가
- [ ] 이 그림을 문서에 넣었을 때 축소돼도 읽히는가

## 결과 기록

검토 후 아래 중 하나를 명시한다.

- **통과** — 전 항목 ✓. 이제 "완료" 선언 가능.
- **수정 필요** — ✗ 항목과 대상 셀 id 를 적고 `.drawio` 수정 → 린트 → 재캡처.

린트가 통과했는데 눈으로 결함이 보였다면, **그 결함을 잡는 규칙을 만들 수
있는지** 검토한다. 만들 수 있으면 `drawio_lint.py` 에 규칙을 추가하고 fixture 를
`checks/bad-L*.example.drawio` 로 남긴다 — 같은 결함을 두 번 눈으로 찾지 않기
위해서다.
