# Claude 실수 기록 (mistake) v3

> **본 파일은 지시용.** 같은 실수의 반복을 막는 self-contained 단일 근원(SSOT / Single Source of Truth). v2(문서 중심 — 항목 형식·카테고리 enum·격상 사다리·수기 INDEX)를 **전면 대체**한다. 본문 외 가이드라인·도구·Skill 의존 0.

## 왜 v3 인가 (설계 원리)

v2 는 사건 기록의 산출물을 **문서**로 두었다. 20개 절 중 17개가 "어떻게 쓰고 정리할 것인가"(항목 형식·frontmatter 5필드·category 11종·type 재분류·기각 청소·INDEX 템플릿·격상 사다리)였고, 그 기록이 **다음 편집을 바꾸는 경로**는 1개 절뿐이었다. 그 하나마저 `status: open` entry 만 검사해서, 재발 방지 처방이 들어 있는 **닫힌** 사건은 두 번 다시 읽히지 않았다.

실측(2026-08-30, 사건 8건):

| | |
|---|---|
| 반영 자산이 그 사건을 역참조 | **1/7 (14%)** — "반영했다"가 검증되지 않는다 |
| 닫힌 사건의 읽기 경로 | **0** |
| 규칙 44조항 중 기계 강제 태그 | **0** — 무엇이 강제인지 문서가 말하지 않았다 |
| INDEX | 수기 운용 → 계열 누락. 미운용 저장소에서는 부재 |

현장 보고가 이 구조를 그대로 확인했다 — 처방은 기록됐으나 자산에 박히지 않았고, INDEX 로 찾을 수 없었고, 그래서 **같은 실수가 옆 서브시스템에서 그대로 재발**했다(그리퍼는 고쳤는데 도킹 스택은 그대로).

**v3 의 원리 한 줄: 사건 기록의 산출물은 문서가 아니라 검사다.**

## 0. 핵심 판정 — 재현되나?

사건이 나면 **먼저** 이것만 판정한다. 나머지는 여기서 갈린다.

| | A. 검출 가능 | B. 검출 불가 |
|---|---|---|
| 정의 | 그 실수를 재현하면 기계가 알아볼 수 있다(코드 패턴·파일 상태·명령 결과) | 판단·소통의 실패라 검사할 지점이 없다 |
| 산출물 | `detectors/<id>.sh` — 재현하면 **exit 1** | `detector: none` + 왜 불가한지 1줄 |
| closure | **검사가 실재하고 자기 사건을 잡는가**(기계 검증) | **작업 시점 전달 경로가 있는가** |
| 전파 | 러너가 전 저장소에서 돌린다 — 사건에 이름이 안 적힌 파일도 걸린다 | 파일·계열 토큰 일치로 그 자리에 전달 |
| 예 | 셸 `local a; [ $? …]`(죽은 단언) · 경로 미지정 `reset --hard` · 이력 주석 | "이미 결정된 것을 재질문" — 질문은 도구 호출이 아니라 걸 지점이 없다 |

**A 를 B 로 낮추지 않는다.** "검사를 못 만들겠다"는 판정은 사유 1줄과 함께 남기며, 그 사유가 틀린 것으로 드러나면 사건을 다시 연다. v2 의 실패가 정확히 이 자리에서 났다 — 검사 가능한 사건을 산문 처방으로 닫았다.

## 1. A류 — 검출자 규약 `⟦CI:detectors⟧`

- 위치: 번들 `detectors/<entry-id>.sh` — **번들에 둔다.** 여기 두어야 다른 저장소·다른 서브시스템에서 같이 돌아간다. 사건이 난 프로젝트에만 두면 전파가 없다(v2 의 실패).
- **이미 다른 번들의 이빨이 그 실수를 잡고 있으면 새로 만들지 않는다.** `detector:` 에 그 경로를 적는다(예: `coding/checks/update-entry.sh`). 같은 검사를 두 벌 두면 둘이 갈라지고, 갈라지면 어느 쪽이 진짜인지 아무도 모른다. 이때도 kind 는 A 다 — 기계가 잡고 있다는 사실이 중요하지 검사 파일이 어느 폴더에 있는지는 중요하지 않다.
- 계약: `detectors/<id>.sh <스캔루트>` → 그 실수가 있으면 **exit 1** 과 `파일:줄` 출력, 없으면 exit 0.
- **일반화해서 쓴다** — 특정 파일명이 아니라 패턴으로. 그 사건의 파일만 잡는 검사는 전파되지 않으므로 검사가 아니다.
- 일반화가 불가능하면(그 저장소 고유 배선) 프로젝트 로컬 `docs/claude-mistake/detectors/<id>.sh` 에 둔다. 러너가 둘 다 돌린다.
- 자기 사건을 실제로 잡는지 **음성 대조**로 증명한다 — `detectors/<id>.fixture/` 에 재현 표본을 두면 러너가 "표본에서 exit 1, 고친 표본에서 exit 0" 을 확인한다. 표본 없는 검사는 죽은 검사와 구분되지 않는다.
- 실행: `detectors/run.sh [스캔루트]`. 이빨(`⟦CI⟧`)로 커밋 시점에, 필요하면 훅으로 편집 시점에 건다 — **실행 시점 선택이 곧 강제 강도다.** 별도의 격상 사다리 규칙을 두지 않는다.

## 2. B류 — 전달 규약 `⟦훅:relevance⟧`

검사할 지점이 없는 사건은 **그 자리에 가져다주는 것**이 유일한 대응이다. 읽으라고 적어 두는 것은 대응이 아니다.

- `hooks/mistake-relevance.py`(PreToolUse)가 코드 파일을 고치려 할 때, 그 파일에 걸린 사건의 **§재발 방지 본문**을 낸다. **open·closed 를 가리지 않는다** — 처방은 닫힌 사건에 있다.
- 걸리는 방식 3가지: ① 그 파일이 사건의 자산 ② 사건 본문이 그 파일을 다룸 ③ **사건이 다루는 코드 토큰 2개 이상이 그 파일에 있음**. ③이 전파 경로다 — 사건에 이름이 적히지 않은 파일은 ①②로는 영원히 안 걸린다.
- **차단은 강한 근거(①)에서만.** ②(토큰 일치)는 전파 발견용이라 어휘가 겹치는 것만으로 걸린다 — 실사격에서 무관한 사건이 낱말 두 개 때문에 이 훅 자신의 수정을 막았다. v2→v3 **재판정 대기**(`사유 미기재`)도 차단하지 않는다: 누군가 판정해서 미해결로 둔 것이 아니라 이행이 일괄로 열어 둔 상태라 근거가 없다. **커진 차단은 우회로 무력화된다.**
- 그 밖은 안내만 한다. 세션당 사건 1회. 판정이 아니라 후보 제시이므로 오탐은 무해하다.
- 세션 시작 요약은 `hooks/mistake-inject.py`(SessionStart), 미해결 사건 선독 강제는 `hooks/mistake-relevance.py` 가 함께 맡는다(v3 에서 통합 — 나뉜 채로 둘 다 목적을 놓쳤다).

## 3. entry 형식

frontmatter 4 필드 + 본문 4 절. v2 의 5필드·5절에서 `reflected_assets`(검증 불가한 파일 목록)와 §사용자 지적(§무엇이 잘못이었나에 흡수)을 뺐다.

````markdown
---
id: YYYY-MM-DD-NNN
kind: A | B                 # §0 판정. A 는 detector 필수
detector: detectors/<id>.sh | none (<불가 사유 1줄>)
status: open | closed | retracted
---

# YYYY-MM-DD HH:MM (KST) — <짧은 제목>

## 무엇을 했는가
시도한 행동·작성한 내용과, 사용자가 어떻게 교정했는지.

## 무엇이 잘못이었나
어긴 규칙의 명시 인용(파일 §절 `:L번호`) 또는 어긋난 결과.

## 원인 분석
왜 그 자리에서 막히지 않았는가 — 규칙 부재인가, 있는데 안 보였는가, 보였는데 검사가 없었나.

## 재발 방지
A: 검출자가 무엇을 어떻게 잡는지 + 음성 대조 결과. B: 왜 검출 불가인지 + 전달로 무엇이 뜨는지.
````

`category` 는 검색 라벨로 자유롭게 붙일 수 있으나 **closure 조건이 아니다.** 분류의 정확성이 재발을 막지 않는다.

## 4. Closure 규칙 `⟦CI:entry-lint⟧`

`status: closed` 는 기계가 확인한다. 산문으로 닫지 못한다.

- **A류** — `detector` 파일이 실재하고, 러너가 그 검사를 통과시킨다. 표본이 있으면 표본에서 exit 1 이 나와야 한다(죽은 검사 차단).
- **B류** — `detector: none (<사유>)` 가 사유를 갖추고, `mistake-relevance` 가 그 사건을 낼 수 있어야 한다(본문에 코드 토픽 백틱 인용 2개 이상 — 걸림 조건).
- **재발** — 같은 검사가 있는데 또 났으면 검사가 부족한 것이다. 검사를 고치고 표본을 추가한다. 새 사건을 여는 대신 **원 사건을 다시 연다.**
- `retracted`(오판 기각)는 v2 절차를 유지한다 — 검출자·전달에서 제외하고, entry id 로 grep 해 오염을 청소한다.

## 5. INDEX — 생성물 `⟦CI:index-gen⟧`

`docs/claude-mistake/INDEX.md` 는 **손으로 쓰지 않는다.** `checks/index-gen.py` 가 entry frontmatter 와 `detectors/` 에서 생성한다: 사건 표(id·kind·detector·status·제목), 검출자 목록, 미해결 항목, **키워드 색인**(사건이 다루는 코드 토큰 → 사건 id). 수기 요약은 계열이 빠지고, 빠지면 찾을 수 없다.

## 6. 검토 시점

- **세션 시작** — `mistake-inject`(SessionStart)가 INDEX 요약과 미해결 사건을 준다.
- **코드 수정 직전** — `mistake-relevance`(PreToolUse)가 **그 파일에 걸린 사건**을 낸다. 미해결(open)이면 차단, 닫힌 사건이면 처방을 안내한다. **무관한 사건으로는 막지 않는다.**
- **커밋 시점** — `detectors/run.sh` 와 `entry-lint.sh` 가 검사·형식·closure 를 재도출한다.

## 7. 자체 점검

```bash
bash checks/entry-lint.sh docs/claude-mistake     # 형식·closure
bash checks/check-mapping.sh                      # ⟦CI⟧·⟦훅⟧ 태그 ↔ 실물 1:1
bash detectors/run.sh .                           # 전 검출자 실행
python3 checks/index-gen.py docs/claude-mistake   # INDEX 재생성(--check 로 신선도)
```

## 8. 변경 절차

SSOT 는 본 번들 폴더다. 규칙 변경은 사용자 승인 후 `mistake.md` + `checks/*` + `hooks/*` + `detectors/*` 를 **단일 VERSION 으로 동반 갱신**한다. `⟦CI:<id>⟧`·`⟦훅:<id>⟧` 태그를 추가·변경하면 실물과 계약 테스트를 함께 갱신한다 — 태그↔실물 짝은 `check-mapping.sh` 가 지킨다.
