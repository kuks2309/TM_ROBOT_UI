# Git 커밋·푸시 워크플로 v3 (격리 모델)

> **본 파일은 지시용.** Git commit/push 와 다중 세션 작업 규칙의 self-contained 단일 근원(SSOT / Single Source of Truth). v2(공유 트리 + 하드블록 게이트 25종)를 **전면 대체**한다 — 게이트로 겹침을 막지 않고 **격리로 겹침을 없앤다**.

본 코어는 self-contained 다 — 본문 외 가이드라인·도구·Skill 의존 0.

## 왜 v3 인가

v2 는 여러 세션이 **한 작업 트리를 공유**하고 정확성을 휴리스틱 훅이 하드블록으로 강제했다. 그 훅들(edit-guard·scope-gate·신선도·claim 장부…)이 오탐·브릭·마찰을 재생산했다. v3 는 뿌리를 없앤다: **한 세션 = 한 트리.** 겹칠 것이 없으면 막을 것도 없어 게이트가 통째로 삭제된다.

전체 원리·근거는 같은 폴더 **[one_session_one_tree.md](one_session_one_tree.md)** 4원칙이 SSOT 다. 아래는 그 구현 요약이다.

## 4원칙 (SSOT: one_session_one_tree.md)

1. **격리** — 세션별 자기 `git worktree`. 세션 간 같은 파일 수정 금지. 부득이 공유 시에만 통지.
2. **수정** — 수정 전 `origin/main` 최신 rebase → 그 위에서 고침 → 수정 후 즉시 safepush.
3. **배포** — 자기 세션 수정분만 기록. 타 세션 내용 절대 미기록.
4. **정리** — 세션 종료 요청 시 정산(safepush) 후 worktree 삭제. 종료 훅을 못 돈 worktree(작업 중 탭 닫힘 등)는 다음 세션 시작 훅이 **주인 세션 종료가 확인되고 잃을 것이 없을 때만** 지운다(reflog 에만 남은 커밋은 보관 ref 로 옮겨 «잃을 것 없음» 으로 만든 뒤).

> **합치기(수렴)는 별도 원칙 아님** — 2로 main 이 늘 최신이라 따로 합칠 게 없다. 파일 독립이면 합칠 것도 없고, 같은 파일도 "수정 전 최신 보고 수정"으로 순차 처리된다. 진짜 동시(같은 파일)만 safepush 의 rebase 충돌(exit 3)로 드러나며 그때만 사람에게 통지한다.

갱신되면 표시를 지워 다음 막힘은 곧바로): main 이 아닌 브랜치·detached, main 의 upstream 이 origin/main 아님, 진행 중인 git 작업, 10분 넘은 `index.lock`, 원격에 없는 커밋, 열린 세션이 부르는(감싸지 않은) 훅 스크립트가 원격에서 지워짐(HEAD·작업본 `settings.json`·`settings.local.json` 의 `$CLAUDE_PROJECT_DIR/…`·`"$CLAUDE_PROJECT_DIR"/…` 경로, 심볼릭 링크를 푼 경로, 그 파일을 품은 폴더·링크가 지워지는 경우 포함), 받을 파일에 체크아웃 필터가 걸림(필터 설정이 있고 `filter` 속성이 걸렸거나 받을 `.gitattributes` 가 `filter=` 를 담음 — 설정만 있으면 갱신), 겹침, 방금 바뀐 받을 파일로 1시간 넘게 미룸. 조용히 다음 정리로 미루는 경우: 꺼진 클론, 막 생긴 `index.lock`, 받을 파일 중 60초 안에 바뀐 것(미래 시각은 제외). merge 바로 앞에서 브랜치·HEAD·가드를 다시 본다. merge 가 도중에 **폐기된 v2 게이트**: `edit-guard`·`scope-gate`·`hash-sweep`·`track`·claim 점유 장부·기록 파일 예외·override 체계 — 격리로 불필요해져 삭제.

## push 대상 — origin 만

routine 커밋·푸쉬는 **origin 만**. `fito` 등 배포 미러는 개발 저장소 전용이며, 필요 시 수동 동기한다(매 커밋 동기는 발산·브릭 위험만 늘림). 배포 대상 저장소에는 fito 원격을 두지 않는다.

## 배포·설치본 검증

- `--status` 는 설치된 파일의 VERSION 문자열을 번들 SSOT 와 **실물 대조**(기록 아님).
- install.sh 는 **통째 교체(디렉터리 스왑)** — 원본 외 잔재 0. 설치 직후 실물 VERSION 검증.
- **번들과 settings.json 은 프로젝트 저장소에 함께 커밋한다**(3.3.0 — 사용자 결정 2026-10-24, 작업 흐름 재설계 `docs/design/2026-10-24-workflow-redesign.md` P0-1).
  그전에는 «커밋하지 않는다» 였는데, 그 결정은 git_workflow 번들만 지켜져 저장소마다 규칙·훅 등록 사본이 여럿으로 갈라졌다
  (세션 트리는 커밋된 옛 버전, 주 트리는 설치본 — 잠든 등록·없는 파일을 가리키는 등록이 생김). 원래 이유(«clone 이 등록만 받고 훅 파일은 못 받아 브릭»)는
  번들 파일과 등록을 **같은 커밋**에 넣으면 생기지 않는다.
- 설치는 세션 트리에서 `tools/install-to-repo.sh --tree <세션 트리> --session <id> <번들 폴더>` 로 한다 — 번들 하나씩, 설치기를 돌린 뒤
  CLAUDE.md 는 시작·끝 표식 쌍 사이만 정본 스니펫으로 교체(쌍 밖 프로젝트 규칙 보존), settings.json 은 끈 목록(`.claude/hooks-disabled.txt`)을 걷고
  같은 등록은 나중 것만 남기고 `test -f "<스크립트>" || exit 0;` 로 감싼 뒤, 바뀐 경로만 커밋·safepush. CLAUDE.md 가 바뀌면 차이를 보이고 `--yes` 없이는 커밋하지 않는다.
- **이 클론에서만 켠다** — 시작·종료 훅은 그 클론의 `git config claude.workflow` 가 `on` 일 때만 worktree 를 만들고 정산·push 한다(`on` 외의 값은 끔).
  install.sh 가 설치한 클론에서 켠다. 값이 **없으면** 그 저장소의 세션 트리(`<저장소>-ses-*`)가 이미 있을 때만 켠 것으로 본다 — 격리를 쓰던 클론이
  커밋된 3.3.0 을 받기만 해도 격리가 꺼지지 않게(시작 훅이 «미설정 — 켠 것으로 본다» 를 알림). 커밋된 번들을 받기만 한 다른 클론에는 세션 트리가 없어
  켜기 전까지 아무것도 하지 않는다(종료 때 자동 `git add -A` + push 가 퍼지지 않게).
- 설치 도구는 설치기를 돌린 뒤 커밋까지 가지 못하면(설치·후처리 실패, CLAUDE.md 확인 필요) 트리를 설치 전으로 되돌린다 — 남겨 두면 종료 훅의 정산이 확인 없이 올린다.
  push 안 된 커밋·진행 중인 git 작업이 있는 트리는 거부한다. 설치기가 만드는 `.claude/settings.json.bak` 은 추적되지 않으면 지운다(이력이 백업).
- 감싸기 형식은 `test -f "<스크립트>" || exit 0; <명령>` 이다. 셸 낱말로 읽어 `$CLAUDE_PROJECT_DIR/…` 스크립트(확장자 `.py .sh .bash .js .mjs .cjs .ts .rb .pl`)를
  하나만 부르는 명령만 감싼다 — 디렉터리·경로 둘·셸로 못 읽는 명령은 그대로 둔다. 이미 감싼 명령(`test -f …`·`[ -f … ]`)은 다시 감싸지 않는다.

3.1.2 — **종료 훅 보존 구멍 보강(3.1.1 독립 리뷰 COMMENT 반영).** 3.1.1 은 «push 못 한 커밋 보존»을 push 결과(rc≠0)로 걸어 ① safepush 파일이 없으면(rc 기본 0) 커밋이 고아가 됐고 ② `session/<sid>`·`-end` 가 이미 있으면 이름을 못 붙인 채 트리를 지웠고 ③ `origin/main` 이 없으면 판정 실패를 «0건» 으로 읽었다(셋 다 리뷰가 재현). 이제 커밋으로 판정한다 — `rev-list HEAD --not --remotes` 가 0 이 아니거나 실패하면 `session/<sid>`(차 있으면 `session/<sid>-<짧은 sha>`)로 남기고, 그것도 못 하면 «[정리 보류]» 로 트리를 남긴다. 함께: 같은 이름 tag 가 있으면 `%(refname:short)` 가 `heads/…` 가 되어 삭제가 실패하던 것(전체 ref 이름 사용), 원격 삭제를 push 한 번으로 묶음(lease 여러 개, `--porcelain` 으로 결과별 판정 — SessionEnd 시간 한도에서 왕복 수만큼 잘리지 않게), git 자격 증명 입력 대기 차단(`GIT_TERMINAL_PROMPT=0`·ssh BatchMode), 객체 아닌 입력·예외에도 exit 0. 남은 것(리뷰 지적, 이 판 밖): wip 커밋이 pre-commit 훅에 거부되면 미커밋 파일이 `remove --force` 로 사라짐(기존 결함), safepush 시간 초과 시 자식 git 이 계속 도는 동안 트리를 지울 수 있음(미확인), 종료 훅이 다시 못 만드는 무시 파일(`.env` 등)도 지움(기존). **fix 연쇄 2/3**.

3.1.1 — **종료 시 세션 브랜치 정리.** 원칙4(one_session_one_tree.md)는 «worktree(및 세션 브랜치)를 삭제한다»인데 종료 훅은 `worktree remove` 만 했고, 그 명령은 브랜치를 남긴다. v3 트리는 detached 라 브랜치가 없다는 전제였지만 세션 안에서 모델이 `git switch -c session/<id>`·보존용 `git branch session/<id>-…` 를 만들어 쌓였다(실측: LGIT-C6-Cobot 2026-10-23, 로컬 `session/*` 23개 중 18개가 main 에 다 들어간 빈 껍데기, 23개 중 14개의 끝 커밋이 이 훅의 «종료 정산»). 종료 훅이 worktree 삭제 뒤 이 세션 브랜치 중 origin/main 에 다 들어간 것을 로컬·원격에서 지운다(원격은 `--force-with-lease` 로 우리가 본 값일 때만). 함께 막은 구멍: push 실패(exit 1·4) 때 detached 트리의 미반영 커밋이 트리 삭제와 함께 고아가 되던 것 — `session/<sid>` 로 남겨 시작 훅 미회수 경고가 잡게 한다. 한계: 시작 훅의 잔류 정리(`--sweep`)가 지운 worktree 의 브랜치는 이 정리를 거치지 않는다. **fix 연쇄 1/3**.

3.1.0 — **잔류 worktree 자동 정리.** 작업 중에 탭을 닫으면 종료 훅(SessionEnd)이 돌지 않아 worktree 가 주인 없이 남았다(실측: SDC-MoMa-ses-08f3dd7d, 2026-10-12 18:31 탭 닫힘 → 5일 잔류, 종료 훅 실행 기록 0). 시작 훅이 자기 worktree 에 주인 프로세스 목록을 적어 두고, 백그라운드 정리가 적힌 주인이 모두 사라진 worktree 중 잃을 것이 없는 것만 지운다(훅 시간 제한과 무관). 주인 판정을 「Claude Code 실행 목록에 없음」으로 하지 않는다 — 세션 안에서 띄운 `claude`·팀원 프로세스는 그 목록에 오르지 않아 살아있는 세션을 죽었다고 볼 수 있다. 정리와 resume 이 겹치는 경합은 worktree 별 잠금(`<git 공용 디렉터리>/claude-residue/<이름>.lock`)과 「잠금 안에서 재확인 → 옮긴 뒤 삭제」로 막고, 주인을 못 찾은 세션은 「주인 모름」 항목과 10분 사용 표시로 정리 대상에서 뺀다(독립 리뷰 3회 지적 반영). fetch 시간 제한 15 s → 3 s(등록 timeout 5 s 안에서 안내문이 나가게). 한계: ① 프로세스 작업 폴더만 보므로 절대경로로 그 worktree 를 쓰는 다른 프로세스는 못 본다 ② 이 판 이전에 만든 worktree·이 판 설치 뒤 아직 다시 시작하지 않은 세션의 worktree 는 주인 기록이 없어 정리 대상이 아니다 — 설치 시점의 잔류물은 손으로 한 번 정리한다 ③ POSIX 전용(잠금에 `fcntl`) — Windows 에서는 정리하지 않고 안내만 한다 ④ 한 번이라도 주인을 못 찾은 worktree 는 「주인 모름」 항목이 남아 영구히 정리하지 않는다(그 프로세스가 아직 살아있을 수 있어 지우지 않는 쪽을 택함) ⑤ 지우다 멈추며 `.git` 파일까지 지워진 `.…removing-` 폴더는 상태를 못 읽어 알림 없이 남는다(데이터 손실 아님) ⑥ 사용 표시 유예(10분)는 벽시계 기준이라 시계가 크게 뛰면 짧아질 수 있다(주인 생존 판정이 먼저 막는다).
