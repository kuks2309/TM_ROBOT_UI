# ADR 템플릿 (필드명 정본)

> **본 파일이 ADR 필드명의 단일 근원(Single Source of Truth)이다.** 기계 검사는
> `checks/adr-fields.sh` 가 수행하며, 아래 표기 중 어느 것이든 인정한다.
> 이 파일이 없기 전에는 검사기 정규식이 유일한 사양이어서, 저자는 무엇을 써야 하는지
> 문서로 알 수 없고 검사기는 저자 관행을 몰랐다 — 그 불일치가 대량 오탐의 원인이었다.

## 필수 5필드

| 필드 | 무엇을 적나 | 한국어 표기(허용) |
| --- | --- | --- |
| **Status** | Proposed / Accepted / Superseded + 날짜·검증 상태 | 상태 |
| **Context** | 왜 결정이 필요한가 — 사실·제약·1차 source | 맥락 · 배경 · 문제 |
| **Decision** | 무엇을 정했나 — 명령형 단정 | 결정 · 채택안 |
| **Consequences** | 그래서 무엇이 달라지나 — 이득·비용·남는 위험 | 영향 · 결과 · 파급 · 귀결 |
| **Rollback** | 되돌리는 절차. 가역이면 `N/A (가역)` 이라도 **명시** | 롤백 · 되돌리기 · 원복 · 복구 |

Rollback 을 가역 변경에서도 요구하는 이유: "비가역인지"를 기계가 판정할 수 없기 때문이다.
저자가 `N/A (가역)` 한 줄을 쓰는 비용은 0에 가깝고, 그 한 줄이 "되돌림을 생각은 했다"는
증거가 된다. 비가역 변경(영속 상태·스키마·펌웨어)은 `N/A` 가 아니라 **실제 절차**를 적는다.

## 인정되는 표기 3형태

```markdown
## Status                    ← 제목형(표준)
## 상태                      ← 제목형(한국어)
## 1. Context (배경)         ← 번호 붙은 제목
### 3-1 맥락
- Status: Accepted           ← 목록형 라벨(콜론 필수)
- **상태**: 채택
**Rollback**: N/A (가역)
```

콜론 없는 산문(`## 결정된 사항은 …`)은 라벨로 인정하지 않는다 — 오인식 방지.

## 최소 예시

```markdown
# ADR YYYY-MM-DD — <한 줄 제목>

- **Status**: Accepted — YYYY-MM-DD (실기 검증 완료 / 미검증 명시)

## Context
<사실·제약. 추정은 추정이라고 쓴다.>

## Decision
<정한 것. 기각안이 있으면 ## Alternatives 로 분리.>

## Consequences
<이득 / 비용 / 남는 위험·부채(있으면 debt id 참조).>

## Rollback
<되돌리는 절차. 가역이면 "N/A (가역)".>
```

`docs/adr/` 에는 **ADR 만** 둔다. 브리프·계획서처럼 Status/Decision 이 없는 문서를 같은
폴더에 두면 검사기가 영구 실패하고, 그 실패가 정상이 되면 검사 자체가 죽는다.
